Pawservation AI Chat Agent

A production Claude Haiku 4.5 agent with fifteen tools, two-phase confirmation, a circuit breaker, and no authority over money.

Live

Customers book in plain language, on the client portal and on the multi-tenant platform. The agent runs on Claude Haiku 4.5 through the Vercel AI SDK with fifteen tools wired to the live system: schedule, reschedule, cancel, pull history, send a receipt. The prompt was the easy part; the safety envelope took the rest of the time. The constraint I care most about is that the model has no authority over money: prices, balances, and fees come from the same server-side logic the invoice uses and are reported verbatim, so the assistant narrates figures it cannot compute — enforced in code, not in the prompt. Every mutation goes through one preview-and-confirm gate, and the code path that performs a write calls no model. So an injection that lands, through booking notes, ingested mail, or the titles of synced third-party calendar events, can make the assistant say something false. It cannot make a write happen.

Agent & Safety Envelope
  • Shipped a customer-facing Claude Haiku 4.5 agent (Vercel AI SDK, 15 tools) for booking, rescheduling, cancellation, history, and receipts, streaming responses over the live system
  • Gated every mutation behind an explicit confirmation card backed by a single-use KV token (5-min TTL), blocking any destructive action from running without approval
  • Implemented layered cost controls: per-user rate limiting (20 msg/hour), daily token budgets (50k tokens/day), hard USD spend caps at the platform, tenant, and client level, and a circuit breaker (3 failures, then a 60s cooldown)
  • Designed chat persistence with a 20-message sliding window, automatic session rotation at 100 messages, and a 90-day retention cleanup cron
  • Wrote an automated LLM eval harness run on every prompt change against production tool schemas, catching a regression that fired on roughly one in nine agent runs and that manual testing had missed
  • Threat-modeled the agent's attack surface (prompt injection, tool authority, data exfiltration) before wiring it to live billing and scheduling data
Money & Authority
  • Kept every price, balance, and fee in existing server-side logic and reported it verbatim, so the model narrates figures it cannot compute
  • Registered every dollar figure a tool returns for the turn and discarded the entire answer when the model's prose contained an amount not in that set, rather than stripping the number and shipping a still-unverified sentence
  • Proved the model never receives the inputs it would need to do arithmetic: for a date-range quote, a test stringifies the whole prompt and every tool result and asserts the only digits present are the two dates — no rate, no count, nothing to multiply
Mutation Gate & Injection
  • Routed every mutation through one preview-and-confirm gate where the server resolves the intent and writes the confirmation text itself, minting a single-use token bound to that exact action and re-checking it against live state before applying
  • Kept the code path that performs a write free of any model call
  • Reduced prompt injection from a correctness risk to a nuisance by requiring a human to approve text the server authored — untrusted text arrives from booking notes, ingested mail, customer intake answers, and titles of synced third-party calendar events
  • Declined to delegate confirmation to the AI client, since whether a given client shows a tool call to its user before approving is outside the product's control and unverified
Why it matters: the usual guardrail is a prompt telling the model to be careful with money. This one removes the capability instead — the model never receives the numbers it would need to do arithmetic, and the write path does not call it. The circuit breaker sits at the agent layer rather than the model layer, so it still protects the downstream tools when the model itself is the thing misbehaving.

Pawservation MCP Server

A standards-conformant Model Context Protocol server with hand-written OAuth + PKCE, stateless on Workers V8.

Spec-strict

The MCP server exposes the booking system to MCP clients, so I and a customer's own AI assistant can drive it from Claude Desktop, Cursor, or anything spec-compliant. I hand-wrote the authorization-code flow with PKCE — RFC 7636 on the portal server, the full MCP authorization spec on the platform — so any spec-compliant client connects self-service, and the platform server is publicly verifiable at its discovery endpoint rather than something you have to take my word for. It's stateless across the Workers V8 fleet: every request stands alone, every token is verified, nothing held in memory between calls. The part I would point a reviewer at is that customer chat and the MCP connector are one product through two transports: capabilities are declared once and implemented once, and the binding fails loudly in both directions if the two ever disagree. MCP Auth Kit (below) is the open-source version of the auth and safety layer underneath it.

Debrief

A native macOS app that records job-interview calls locally, transcribes them on-device, and turns them into LLM-scored coaching feedback.

Open source

Debrief records your interview calls, transcribes them on-device, and scores them against a rubric, so you walk into round two knowing what to fix. The core idea is dual-stream capture: your mic and the interviewer's audio (via ScreenCaptureKit) record as two independent tracks, so who-said-this is a hardware-level fact instead of an ML diarization guess — nothing joins the call as a visible bot. WhisperKit (CoreML/Metal) transcribes fully on-device; the Claude API then produces per-dimension scores, weakness tags, and action items. Paste a company's actual leveling guide and the model weights it above the built-in rubric for that session; an offline mode runs coaching against a local model instead. Audio flushes to disk in chunks during recording, so a crash mid-interview never loses a session, and a trends view charts recurring weakness tags across companies and rounds. Built solo as a native Swift Package with five independently testable targets, each covered by automated tests — including a real end-to-end WhisperKit integration test.

Roadrunner

A multi-user Django app that shares the nature you saw on your Strava activities — matching eBird and iNaturalist observations by time and location.

Open source

Log in with Strava, link an eBird or iNaturalist profile, and Roadrunner writes the species you logged into the description of the matching Strava activity. Activities sync in real time via Strava OAuth and webhooks, with automatic token refresh. The interesting problem: birders submit checklists hours after they get home, so unmatched activities go into a deferred re-check queue (2/4/8-hour ladder), and the species appear the moment the checklist does. Deployed serverless on Vercel with pooled Neon Postgres and scheduled by a bearer-authenticated GitHub Actions cron. Three third-party API integrations, timezone-correct wall-clock matching, security middleware (CSRF, clickjacking, per-user webhook rate limiting), and a test suite covering matching, sync, OAuth, and the re-check queue.
